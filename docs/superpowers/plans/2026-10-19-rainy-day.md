# rainy-day Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin that enforces plain-language usage budgets against the 5-hour and weekly plan meters, warns near the limit, stops tidily at it, and shelves work for after the reset.

**Architecture:** Pure TypeScript modules (usage parsing, limit maths, gate decisions, shelf) with thin hook entry points and one CLI (`rainy-day`, on the Bash PATH via `bin/`). Usage comes from `claude -p "/usage"`, cached on disk. A skill teaches Claude to turn requests into CLI calls.

**Tech Stack:** TypeScript 5 → `tsc` → committed `dist/`; Node ≥ 22; vitest for tests; no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-rainy-day-design.md`

## Global Constraints

- No runtime dependencies. `dist/` is committed and is what hooks and `bin/` run.
- Never read OAuth tokens or call HTTP endpoints. Usage only via `claude -p "/usage"`.
- Unparseable or unavailable usage ⇒ "usage unknown", never 0%. Unknown never blocks work, and is always reported to the user.
- Heads-up threshold: within 5 points of `stopAt`, shown once per limit.
- Every hook exits immediately (no output, exit 0) when `RAINY_DAY_PROBE=1`.
- State dir: `$RAINY_DAY_HOME` if set, else `~/.claude/rainy-day/`. (Spec said `${CLAUDE_PLUGIN_DATA}`, but Bash-tool commands don't receive that variable, and the CLI and hooks must share one dir. Update the spec's wording in Task 1.)
- Messages use "5-hour" and "weekly" for the meters.

## Review Focus

- **Weekly already past the requested line** (e.g. at 77%, "keep 25%" ⇒ 75%): `set` must still save it and report it as already reached, so the next tool call trips it. Test in Task 4.
- **Breakdown percentages in `/usage`** ("97% of your usage came from…") must never be read as a meter. Test in Task 2.
- **Reset time with no date / year rollover** ("resets 8:30pm", "resets Jan 2 at 7am" seen on Dec 30). Test in Task 2.
- **Shelve command during lockout** must get through the gate, including a heredoc body; a chained command (`rainy-day x && rm -rf …`) must not. Test in Task 5.
- **Stale cache when `claude` binary is missing**: last-known snapshot older than 30 min must not be trusted as current. Test in Task 3.

Shared types (defined in Task 2/4, used everywhere):

```ts
type Meter = 'session' | 'weekly';           // session = 5-hour
interface MeterReading { usedPct: number; resetsAt: number /* epoch ms */ }
interface UsageSnapshot { session?: MeterReading; weekly?: MeterReading; fetchedAt: number }

interface Limit {
  id: string;                 // short, e.g. 'w75'
  meter: Meter;
  stopAt: number;             // absolute percent
  scope: { kind: 'global' } | { kind: 'session'; sessionId: string };
  until: { kind: 'cleared' } | { kind: 'reset'; at: number } | { kind: 'date'; at: number };
  label?: string;             // the user's words
  createdAt: number;
  warned: boolean;
  trippedAt?: number;
  graceLeft?: number;         // starts at GRACE_CALLS = 5 on trip
}
```

### Task 2: Parse `/usage`

**Files:** Create `src/usage/zoned.ts`, `src/usage/parse.ts`, `test/usage/parse.test.ts`, synthetic fixtures in `test/fixtures/`.

**Interfaces — Produces:** `parseUsage(text: string, now: number): UsageSnapshot | null` (null when neither meter line parses); `zonedTimeToEpoch(y, mo, d, h, mi, timeZone: string): number`.

Lines matched (anchored, start of line, after trim):
`Current session: <N>% used · resets <when> (<IANA tz>)` and `Current week (all models): <N>% used · resets <when> (<IANA tz>)`.
`<when>` is `Mon D at h[:mm](am|pm)` or `h[:mm](am|pm)` (no date ⇒ next occurrence after `now`). Year: `now`'s year in that zone; if the result is more than 1 day before `now`, add a year. Zone conversion uses `Intl.DateTimeFormat` offset lookup (guess UTC, measure offset, correct, re-measure once for DST).

- [ ] Tests (fixture `usage-team-2.1.303.txt`, `now` = 2026-10-19T19:00Z): session `{usedPct: 5, resetsAt: Date.parse('2026-10-19T23:30:00Z')}`; weekly `{usedPct: 77, resetsAt: Date.parse('2026-10-22T10:00:00Z')}`.
- [ ] Test: text containing only breakdown lines ("97% of your usage came from…") ⇒ `null`.
- [ ] Test: `resets 8:30pm (America/Halifax)` with `now` 2026-10-19T19:00Z ⇒ 2026-10-19T23:30Z; with `now` 2026-10-20T01:00Z ⇒ 2026-10-20T23:30Z.

### Task 4: Limits

**Files:** Create `src/limits.ts`, `test/limits.test.ts`.

**Interfaces — Produces:**
```ts
GRACE_CALLS = 5; WARN_WITHIN = 5;
loadLimits(): Limit[]; saveLimits(l: Limit[]): void;
addLimit(input: Omit<Limit, 'id'|'createdAt'|'warned'>, now): Limit   // id = meter[0] + stopAt, suffixed -2, -3 on clash
removeLimit(id: string): boolean; clearLimits(): number;
activeLimits(all: Limit[], sessionId: string | undefined, now: number): Limit[]  // drops expired (also pruned on save)
assess(limit: Limit, usage: UsageSnapshot): 'ok' | 'near' | 'reached' | 'no-reading'
describe(limit: Limit, usage?: UsageSnapshot): string   // e.g. "weekly: stop at 75% (now 77% — reached), all sessions, until cleared"
```
`near` = `usedPct >= stopAt - WARN_WITHIN && usedPct < stopAt`. `reached` = `usedPct >= stopAt`. `until.reset` expires when `now >= at`.

- [ ] Tests: session-scoped limit is active only for its sessionId; expired `until` dropped; `assess` boundaries at 69/70/75 for stopAt 75; already-past limit saved and assesses `reached`; id clash ⇒ `w75-2`.

### Task 5: Gate decision

**Files:** Create `src/gate.ts`, `test/gate.test.ts`.

**Interfaces — Consumes:** `activeLimits`, `assess`, `UsageResult`. **Produces:**
```ts
interface HookOut { systemMessage?: string; hookSpecificOutput?: { hookEventName: 'PreToolUse'; permissionDecision?: 'deny'; permissionDecisionReason?: string; additionalContext?: string } }
decidePreToolUse(args: { toolName: string; toolInput: any; sessionId?: string; limits: Limit[]; usage: UsageResult; now: number; unknownReported: boolean })
  : { out: HookOut | null; limits: Limit[] /* mutated copies to save */; reportedUnknown: boolean }
isOwnCommand(toolName: string, toolInput: any): boolean
```
Rules, in order:
1. No active limits ⇒ `out: null`.
2. Usage `ok: false` ⇒ once per session (`unknownReported`), `systemMessage: "rainy-day: can't read usage right now — your limit isn't being enforced."`; allow.
3. Any limit `near` and not `warned` ⇒ set `warned`, `systemMessage: "FYI: you're at 58% weekly, and you want to stop at 60%."` (values filled in).
4. Any limit `reached`:
   - not yet tripped ⇒ set `trippedAt`, `graceLeft = GRACE_CALLS`; allow with `additionalContext` telling Claude: budget reached; finish the current small step only, start nothing new; then tell the user where things stand and ask: keep going (raise/clear the limit with `rainy-day`) or shelve (`rainy-day shelve`). Also `systemMessage: "rainy-day: weekly usage is at 77%, your limit is 75%. Wrapping up."`
   - `graceLeft > 0` ⇒ decrement, allow (repeat the wrap-up context).
   - `graceLeft == 0` ⇒ allow `isOwnCommand` and `AskUserQuestion`; else deny with reason pointing at the same choice.
`isOwnCommand`: `toolName === 'Bash'`, first line of `command` matches `^\s*rainy-day(\s|$)` and contains none of `&&`, `||`, `;`, `|`, `` ` ``, `$(`; any later lines are allowed only if the first line uses a quoted heredoc (`<<'X'` or `<<"X"`).

- [ ] Tests: each rule; warn shown once; trip ⇒ 5 allowed calls then deny; `rainy-day shelve --title x <<'EOF'\n| a | b |\nEOF` allowed under lockout; `rainy-day list && rm -rf x` denied; `AskUserQuestion` allowed; unknown usage reported once per session.
- [ ] Implement, tests pass, commit.

### Task 7: CLI

**Files:** Create `src/cli.ts`, `bin/rainy-day`, `test/cli.test.ts`.

**Interfaces — Consumes:** Tasks 3–6. Session id from `$CLAUDE_CODE_SESSION_ID`.

Commands (output plain text, exit 1 with message on bad input):
- `rainy-day status` — usage readings + active limits via `describe`, or the unknown reason.
- `rainy-day set <session|weekly> <pct> [--add] [--scope session|global] [--until cleared|reset|<ISO date>] [--label "<words>"]` — `--add` means relative to current reading. `--scope session` requires `CLAUDE_CODE_SESSION_ID`. Prints the saved limit via `describe`, and "already reached" when it is.
- `rainy-day clear <id|all>`
- `rainy-day shelve --title "<t>" [--note "<md>"]` — note from stdin if not given and stdin isn't a TTY; meter/reset taken from the currently tripped limit if any.
- `rainy-day shelf [--all]` — this project's shelf, or every project's.
- `rainy-day unshelve <id>`
`bin/rainy-day`: `#!/bin/sh` → `exec node "$(dirname "$0")/../dist/cli.js" "$@"` (resolve symlinks with `cd -P`).

- [ ] Tests (call exported `main(argv, env, stdin): {code, out}` with a stubbed `getUsage`): `set weekly 75` at 77% prints "already reached"; `set session 20 --add` at 16% saves stopAt 36; `--scope session` without session id errors; `shelve` reads stdin note; `clear all`.
- [ ] Implement, build, `chmod +x bin/rainy-day`, `bin/rainy-day status` prints real numbers. Commit.

### Task 8: Hooks, skill, and wiring

**Files:** Create `src/hooks/pre-tool-use.ts`, `src/hooks/user-prompt-submit.ts`, `src/hooks/session-start.ts`, `src/hooks/io.ts` (read stdin JSON, write stdout JSON, probe guard, never throw — on error exit 0 silently and append to `stateDir()/errors.log`), `hooks/hooks.json`, `skills/budget/SKILL.md`, `test/hooks.test.ts`.

- `hooks.json`: exec form, e.g. `{"type":"command","command":"node","args":["${CLAUDE_PLUGIN_ROOT}/dist/hooks/pre-tool-use.js"],"timeout":30}`. PreToolUse matcher `*`; SessionStart matcher `startup|resume|clear`.
- user-prompt-submit: if active limits, `hookSpecificOutput.additionalContext` = one line per limit via `describe` (cached usage only, no refresh — must stay fast). Nothing otherwise.
- session-start: shelf items for `projectKey(cwd)`. Any with `resetsAt <= now` ⇒ `systemMessage: "rainy-day: you shelved \"<title>\" — your usage has reset since. Ask Claude to pick it up."` plus `additionalContext` with the note and an instruction to offer to continue in the first reply. Otherwise ⇒ quieter `systemMessage: "rainy-day: shelved work here (\"<title>\"); your <meter> limit resets <local day/time>."`
- SKILL.md (`name: budget`): triggers on budget/usage-limit requests. Content: interpretation rules from the spec verbatim (up to N% ⇒ `--add`; until N% ⇒ absolute; keep N% ⇒ 100−N); always run `rainy-day status` first; ask scope/duration when unclear; repeat back with numbers before `set`; at a trip, finish the step, summarise, ask keep going vs shelve; shelve note format (task, done, left, how to resume).

- [ ] Tests: run each compiled hook as a child process with JSON stdin and `RAINY_DAY_HOME` temp dir (and pre-seeded `usage.json` so no subprocess): PreToolUse with a reached limit emits the wrap-up context; with `RAINY_DAY_PROBE=1` emits nothing; session-start with a reset-passed shelf item emits the systemMessage.
